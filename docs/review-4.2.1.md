# 4.2.1-beta.1 合并审查

审查日期：2026-10-18。范围为从 4.2.0-beta.5 后的 main 到本次双端导航、共享更新索引、反馈与播放错误修复，包含共享代码、原生宿主、发布工具和当前维护文档。

## 修复的合并问题

| 优先级 | 问题与影响 | 最小修复 |
| --- | --- | --- |
| P1 | Windows 反馈按钮使用内联事件，违反桌面 CSP；此前测试直接调用表单，漏掉真实入口 | 在 `desktop.js` 绑定点击事件；原生测试与真实上传测试实际点击入口，不放宽 CSP |
| P2 | Android 反馈网络与导入/备份共用串行队列，慢网络会阻塞本地操作 | 反馈使用独立的单线程执行队列，随 Activity 关闭；设备回归验证文件队列不被占用 |
| P2 | 发布校验允许同签名的调试 APK，可能错误分发可调试应用 | SDK 校验额外拒绝 `application-debuggable`，发布仍使用 Release 构建及原升级证书 |
| P2 | 发布工具未保证索引小于 Android 读取上限，过长说明会造成 Android 无法检查更新 | 上传前检查完整 UTF-8 索引不超过 64 KiB、APK 不超过 32 MiB；增加超限回归 |
| P2 | Windows 页面重复维护版本字符串，浏览器源码与生成包可能显示不同版本 | 源码保持无版本介绍，构建从 `shared/app-config.json` 注入显示版本与 Tauri 版本 |

反馈入口仅在有原生宿主时显示，旧浏览器迁移页不提供无法使用的网络入口。

另将表单打开前的词库关闭、暂停播放移回各平台适配层，共享表单只处理填写与提交状态；关闭按钮如实命名“关闭”，不表示撤回已经提交的请求。播放错误按当前录音归属与异常类型处理，取消和过期失败不再误报权限问题。

## 架构结论与边界

继续采用两个原生宿主、各自的学习界面和公共数据/偏好模块。更新安装遵循 Android PackageInstaller 与 Tauri 官方更新器，不引入通用安装抽象。两个客户端读取同一个索引，但保留各自的签名协议。表单通过注入函数提交，网络、设备元数据和平台生命周期仍由原生宿主承担。

维护端写入口不进入客户端；反馈仅上传入口可以从客户端中提取，不能当作秘密。已有公开旧版本仍读取旧更新源，需从 GitHub 手动安装一次新版本。Android beta 的历史签名、Windows 尚无 Authenticode、ARM64 未实机验证均是既有发布边界，不声称已经消除。

## 验证入口

- `pnpm --dir tests test`：公共数据、存储、学习与桌面适配。
- `pnpm --dir tests test:browser`：源码与生成包、导航/字体、播放错误分类、反馈失败重试。
- `python tests/test_updates.py`：实际 Minisign 签名、APK 版本/证书/配置/调试属性、双端索引、大小限制、版本文件不可变及最后发布索引。
- `cargo test --locked` 与 `cargo clippy --locked -- -D warnings`：HTTPS/重定向、反馈元数据和官方更新器索引兼容性。
- Gradle `assembleDebug assembleDebugAndroidTest assembleRelease lintDebug lintRelease`，以及 `tests/android/run-device.py`：手机实际导航、100～200% 字号、320dp、主题、音频、导入、更新校验与反馈队列隔离。
- `tests/desktop.cjs`：真实 Tauri WebView2、460 个词条和录音、备份、主题、480～1120px、圆形按钮及 CSP 下的反馈入口。

构建产物、截图、私钥和测试本机配置不入 Git。发布前另以实际签名 APK/安装器执行发布器预检，再对上传文件读回校验；GitHub 与更新目录使用同一组产物。

本次上述检查均通过；Windows 使用本次 Release 二进制并实际点击反馈入口，双端实际提交均得到服务端确认。签名 APK 为 4,439,331 字节，Windows x64 安装包为 6,349,696 字节，发布器已核对真实版本、证书、配置和 Minisign 签名。完整更新安装不在本次重装用户设备；发布后验证根索引和下载读回一致性。
