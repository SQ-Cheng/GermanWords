# 双课程词库实施计划

在现有 `codex/card-layout-feedback-copy` 分支上开发，基线 `17b4782`。先确定数据与状态边界，再逐步实现和提交；本次只开发与调试，不发布新版本。

## 数据与兼容性

- 内置资源放在 `shared/words/german1/` 和 `shared/words/german2/`，只维护一份原始词表；德语（1）文件移动但不改内容，德语（2）仅复制用户提供的 9 份 XLSX，不引入旧 HTML 程序。
- 原始文件不改列、词条、样式或表名。德语（2）未提供录音、例句及 E7/E8，不编造内容，不将其他课程的录音当作该课程资源。
- 德语（1）继续使用原文件名作为存储键，保留星标及 Android 学习进度。德语（2）的内置存储键带稳定课程前缀。导入词表的键全局分配，不随当前课程变化，沿用原有命名和同名冲突处理方式。

## 最小架构

- 新增共享 `library.js`，只管理课程目录、内置/导入文件、稳定词表键与可见列表，不处理页面、解析、播放或原生 API。
- Windows/浏览器适配器继续提供内置文件；Android 适配器继续提供内置及持久导入文件。平台接入共享目录后，仅展示选中课程的内置词表及全部用户导入词表。
- 桌面会话导入保留原有会话生命周期；Android 导入保留原生持久化。选择课程不得替换、删除或隐藏导入词表及其星标。切换课程加载该课程词表，记住课程选择。
- 学习解析和来源标识仍由 `Vocabulary` 处理。录音索引与选择课程解耦；内置课程只能匹配本课程或用户补充的录音，不能回退到另一内置课程。播放器不再凭未匹配的字符串路径猜测内置文件。
- 三端复用课程选择器与分组样式，界面层负责渲染、切换和取消过期读取。避免通用控制器、依赖注入框架、额外服务及重复课程配置。

## 实施与验证

1. 整理与无损引入资源，核对原始字节和解析结果。
2. 实现共享词库目录、课程/导入的稳定身份和录音隔离，增加纯逻辑回归。
3. 接入桌面和 Android 菜单、学习页课程标识、备份与恢复；验证快速切换及导入竞态。
4. 优化三端课程菜单与分组，检查窄窗口、大字号、深浅色、长文件名、空词表和无录音状态。
5. 完成 Windows Tauri 实例、Android 真机及独立浏览器包调试，运行相关构建和静态检查，更新架构、使用与测试文档。

浏览器真机调试使用当前电脑上的实际浏览器；无法据此声称已在 macOS/Linux 设备验证。设备测试工具放在现有 `tests/` 与 Android 标准 `androidTest/`，不进入正式应用。保持现有发布版本号，开发修改逐步提交。
